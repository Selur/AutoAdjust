# Notes for Claude

## Project

Clean-room port of LaTo's closed-source AutoAdjust 2.60: one plugin binary for AviSynth+
(`AvisynthPluginInit3`, function `AutoAdjust`) and VapourSynth API 4 (`autoadjust.AutoAdjust`).
8..16 bit integer YUV/Gray, native high bit depth only (no stacked mode). User documentation is
`README.md`, the behaviour is specified in `docs/SPEC.md`.

- Clean room: code is written from `docs/SPEC.md` only. Never add decompiled code, binary
  addresses or data tables taken from the original DLL to this repository; the original DLL is
  never committed (`.gitignore`).
- `src/core/`: host-independent engine (statistics, temporal window, transform, delta smoothing,
  dither). The C path of the original is reproduced bit-exactly; summation order and strict
  single precision matter (no FMA contraction: `/fp:precise`, `-ffp-contract=off`).
- Threads: the host runs `GetFrame` in parallel; `Engine::windowStats()` takes frames from the host
  through a fetch callback and computes every frame's statistics once (`OnceCache`: the first thread
  claims a frame, others compute their own claims first and then wait; luma histograms are cached the
  same way for the scene change test). `processPlane()` streams rows through a ring of `2 * ry + 1`
  delta rows (thread-local, no frame-sized buffers); `apply()` reads `src` and writes `dst`, so the
  hosts reference or copy only the untouched planes.
- Pixel kernels (`src/core/kernels*.cpp`): vertical/horizontal delta smoothing, the final store and the
  row SAD of the scene change test per instruction set; `kernels_simd.hpp` is one template over a vector traits type, instantiated in
  `kernels_sse2.cpp`, `kernels_avx2.cpp` (only this file is built with AVX2, never with FMA) and
  `kernels_neon.cpp`; `kernels_dispatch.cpp` maps `asm_opt` (0 auto, 1 C, 2 SSE2, 3 AVX2; arm64: 0 NEON).
  Every path must stay bit-identical to `kernels_c.cpp`: same operation order per lane, separate
  multiply and add. The luma/chroma transform is a per-frame lookup table over all sample values.
- NEON without a Mac: build `kernels_neon.cpp` on x86 against Intel's `NEON_2_SSE.h` (not in the repo,
  plus a `vdivq_f32` shim) and compare all kernels with the C kernels on random data; real arm64 runs
  in the macOS CI job (`test_autoadjust.py` checks every available `asm_opt`).
- The static MSVC runtime picks FMA3 variants of `log`/`pow` at runtime; all paths share those calls,
  so paths stay identical, but a CPU without FMA3 may in rare cases round a table entry differently.
- `src/avs_plugin.cpp`, `src/vs_plugin.cpp`: host wrappers. `threads_count` exists only in AviSynth+
  and is ignored there.
- `src/core/bluenoise64.h` is generated by `tools/gen_bluenoise.py`.
- `test/test_autoadjust.py`: VapourSynth functional tests with SHA-256 references; the 8-bit cases
  without dither were checked against the original DLL. Changing pixel output changes the digests:
  regenerate them deliberately (set an entry to `None`, the test prints the new value).

## Build

- `meson setup build && ninja -C build`; on Windows with MSVC `meson setup build --vsenv -Db_vscrt=mt`.
- Wheel: `pip install .` (meson-python, `-Dpython_package=true` installs into
  `site-packages/vapoursynth/plugins`).
- `.github/workflows/build.yml` builds and tests wheels for Windows x64 (MSVC, static runtime),
  Linux x86_64 (manylinux_2_28) and macOS arm64 with cibuildwheel, re-tags them `py3-none`, zips the
  bare plugin binary for AviSynth+, and attaches both to a GitHub release for `v*` tags. Only CI
  builds Linux and macOS; locally only the Windows build is checked.

## Versioning

Version numbers follow semantic versioning strictly. Never bump a version on
your own initiative:

- no bump for CI, packaging or build-system changes
- patch for bug fixes
- minor for backwards-compatible features
- major only for breaking changes

If a change seems to warrant a bump, propose it and let the maintainer decide.

## Format

- Always three parts, `MAJOR.MINOR.PATCH`, and the same number everywhere: the git tag
  (`vMAJOR.MINOR.PATCH`), `version` in `meson.build` (and with it the wheel name), `src/version.hpp`
  and the release title.
- `VS_MAKE_VERSION(major, minor)` in `configPlugin` carries MAJOR and MINOR (from `src/version.hpp`);
  a patch release leaves it unchanged.
- Published releases are never renamed, retagged or rebuilt: their download URLs and SHA-256
  sums are pinned by Hybrid's build scripts.
